Why Headscale?

왜 공식 SaaS 대신 Headscale 사설망인가?

보안 위험 제거와 완벽한 통제권 확보의 4가지 핵심 이유

⚠️ 해결 01

Tailworm 웜 취약점 원천 차단

Tailscale SSH의 소켓/포트포워딩 권한 상승 취약점(Tailworm)과 중앙 SaaS 인증 제약에서 완전히 독립하여, 자체 격리된 제어 서버에서 보안 정책을 100% 직접 통제합니다.

⚡ 장점 02

초저지연 WireGuard P2P 직통망

제어 서버는 최초 노드 키 교환만 조율하고, 실제 트래픽은 머신 간 WireGuard 암호화 직접 통신으로 전달됩니다. 외부 릴레이 서버를 거치지 않아 지연시간이 1~13ms에 불과합니다.

🌐 기술 03

Cloudflare 한계 극복 (ngrok 터널)

Cloudflare는 Tailscale의 POST /ts2021 WebSockets Upgrade 헤더를 강제 제거하여 500 오류가 발생합니다. WebSocket을 온전히 통과시키는 ngrok HTTPS 터널로 공유기 포트포워딩 없이 외부 연결을 달성했습니다.

🔄 편의 04

손쉬운 멀티 프로필 계정 전환

클라이언트를 재설치할 필요 없이 --nickname headscale로 가입되어, tailscale switch 명령어나 트레이 메뉴 클릭 한 번으로 공식 계정과 자유롭게 오갈 수 있습니다.

🔄 4. 계정 목록 확인 및 전환 
tailscale switch --list      # 현재 등록된 계정 확인

FAQ & Lifecycle

인증키 유효기간과 영구 등록의 원리

90일 유효기간이 지나도 이미 등록된 기기는 왜 끊어지지 않는가?

🎟️ 1회성 입장권

이미 등록된 4대 = 영구 유지

사전 인증키(Pre-auth Key)는 최초 기기 등록 시 서버와 신뢰 관계를 맺는 1회성 입장권입니다.

등록 즉시 서버와 기기 간에 개별 NodeKey를 영구 교환하며, 서버의 Expiration: N/A (만료 없음) 정책에 따라 90일이 지나도 재인증 없이 영구적으로 연결이 유지됩니다.

🆕 미래 신규 기기 등록

90일의 의미 = 새 기기 등록 유효창

인증키의 90일 유효기간은 "새로운 기기를 이 키로 등록할 수 있는 기한"을 뜻합니다.

추후 5번째 새로운 PC나 스마트폰을 추가할 때만 서버에서 새 키를 1초 만에 발급받아 등록하면 됩니다: 

docker exec headscale headscale preauthkeys create --user 1 --reusable --expiration 90d
