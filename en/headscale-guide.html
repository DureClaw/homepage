Why Headscale?

Why a Headscale Private Network Instead of the Official SaaS?

4 key reasons: removing security risks and taking full control

⚠️ Fix 01

Block the Tailworm Vulnerability at the Source

Fully independent of the Tailscale SSH socket/port-forwarding privilege-escalation vulnerability (Tailworm) and the constraints of central SaaS authentication, you control 100% of your security policy directly on your own isolated control server.

⚡ Benefit 02

Ultra-Low-Latency Direct WireGuard P2P

The control server only coordinates the initial node key exchange; actual traffic flows directly between machines, encrypted with WireGuard. With no external relay server in the path, latency is just 1~13ms.

🌐 Tech 03

Working Around Cloudflare's Limits (ngrok Tunnel)

Cloudflare strips the WebSockets Upgrade header from Tailscale's POST /ts2021, causing 500 errors. An ngrok HTTPS tunnel, which passes WebSockets through intact, provides external connectivity without router port forwarding.

🔄 Convenience 04

Easy Multi-Profile Account Switching

Registered with --nickname headscale, with no need to reinstall the client, you can switch freely to and from your official account with the tailscale switch command or a single click in the tray menu.

FAQ & Lifecycle

Auth Key Expiry and How Permanent Registration Works

Why don't already-registered devices disconnect after the 90-day expiry?

🎟️ One-time ticket

The 4 Registered Devices = Kept Permanently

A pre-auth key is a one-time ticket that establishes trust with the server when a device is first registered.

On registration, the server and device permanently exchange an individual NodeKey, and under the server's Expiration: N/A (no expiry) policy the connection stays up permanently without re-authentication, even after 90 days.

🆕 Registering new devices later

What 90 Days Means = The Window for Registering New Devices

The auth key's 90-day validity means "the period during which new devices can be registered with this key."

Only when you later add a 5th PC or smartphone do you need to issue a new key on the server (it takes a second) and register it: 

docker exec headscale headscale preauthkeys create --user 1 --reusable --expiration 90d
