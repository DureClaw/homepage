🔑 Keyless access — no secrets handed out in advance

Nodes never need to know a shared secret. A node sends a join request to the server, and once approved the server issues a per-node token. The master secret is never copied anywhere, and each node’s token can be revoked individually.

① Join · auto-approval
Node calls POST /api/join → private network (Tailscale · Headscale) peers are approved instantly (zero-click). Requests from outside wait for operator approval.
② Per-node tokens
The server issues a per-node token → the node caches it and reconnects instantly from then on. The master secret is never exposed, and tokens can be revoked individually.
③ Single commander
Workers only connect, receive and report. Work orders (dispatch) come from the master alone — a worker token cannot issue orders.
Even machines where authentication is awkward, like Windows or an RPi Zero, join as they are. Keyless hands, one brain.

Why DureClaw instead of SSH

SSH exposes "heterogeneous inbound" as is;
DureClaw turns it into "homogeneous outbound + normalized markers".
Linux↔Mac are both POSIX, so it is "one key → done". But the moment Windows joins as a node, the assumptions SSH relies on break on 5 axes at once — the more Windows is involved, the bigger the gap.
Axis SSH — heterogeneous inbound (on Windows) DureClaw — homogeneous outbound
Shellcmd ↔ PowerShell ↔ WSL mixed — quoting and escaping breakThe [SHELL] daemon picks the right shell per OS
PathsC:\… backslashes, drive letters, cd /dPaths passed as is; the node resolves them locally
Encodingcmd code page → mojibake[WRITE:b64] writes the exact bytes
Line endingsCRLF ↔ LF — heredocs and scripts breakbase64 transfer → line endings don’t matter
Authadmins need administrators_authorized_keys + non-inherited ACLs + UAC elevationkeyless registration — inbound auth, firewall rules, elevation: none needed
Measured experiment: on the same task (Mac→Windows, Python→exe build), DureClaw finished the exe in 6 steps with zero setup, while SSH failed authentication 4 times before any work + hit the UAC wall and never ran a single line. The difference is not transfer speed but removing the friction of onboarding, authentication and cross-OS normalization.
🔄 Resilience · visibility — what SSH lacks
Even when the server restarts or upgrades, nodes reconnect automatically (exponential backoff), and a real-time dashboard shows the fleet status. With SSH, a dropped session means reconnecting by hand, and there is no screen showing "who is alive".
Measured: while improving and deploying this project we restarted the server many times, and every node came back on its own each time.
Even on homogeneous Linux↔Linux, SSH keeps structural limits — inbound reachability (impossible behind NAT/firewalls) · 1:N fan-out · persistence · fleet visibility · capabilities beyond the shell. One measured case: on the same Linux box, SSH inbound :22 timed out (couldn’t get in), while DureClaw connected outbound and even built the exe. SSH is a transport pipe; DureClaw is a fleet bus — different layers.

Where it sits — the L4→L0 vertical stack

In the Claude Code ecosystem, most meta-factories emit structure/config at L3 and hand it off to an external runtime. DureClaw not only generates (L3) the team, it also owns the runtime (L1) and physical execution (L0) the team actually runs on, plus the self-improvement (L4) that evaluates outputs and feeds them back — the only vertical stack that has it all in one body. One vertical from self-improvement down to the physical actuator.

L4
RSI / self-improvement ★ unique to DureClaw
5-stage learning loop (observe→synthesize→set goals→codify knowledge→learn & select) + eval + Decision Freezing. Evaluates team outputs, crystallizes them into deterministic skills and feeds them back into L3 patterns — evolving the factory itself. Recursive self-improvement above the meta-factory.
L3
Meta-Factory / Team-Architecture neighbors: Archon · meta-harness
Domain sentence → agent team + skills. /dureclaw 6 patterns(Pipeline · Fan-out/in · Expert Pool · Producer-Reviewer · Supervisor · Hierarchical).
L2
Cross-Harness Workflow neighbors: ECC
Standardized skills, rules and hooks + plugin marketplace loader — common conventions across harnesses.
L1
Orchestration Runtime ★ unique to DureClaw
Phoenix Channel bus + MCP + Work Key + DETS persistence + keyless brain delegation. The distributed message bus where the team actually runs.
L0
Physical Execution ★ unique to DureClaw
edgeclaw(shell, GPIO, signal tower, PA) · webclaw (browser) · deskclaw (GUI). Win, mac, Linux, Pi, riscv — all the way to physical actuators: "approval = physical outcome".
Archon builds runtime determinism. DureClaw uses L4 Decision Freezing to push that determinism straight down to the L0 edge — generation, execution and self-improvement in one vertical.

Ecosystem — one brain, many hands

The master (Claude) is the brain; each claw is a different hand. Over the same bus and the same keyless delegation, it reaches into the physical world, the browser or the desktop. One brain, many hands — one bus, one keyless delegation.
