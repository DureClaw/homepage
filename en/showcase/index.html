SCENE 01 0:00 – 0:15
The problem: Claude Code lives in one window
"I'm using Claude Code on my Mac — and the GPU server next to it is just sitting idle."

Claude Code is running in the Mac terminal. The server terminal is idle. The hassle of switching between two windows, SSHing in and copy-pasting by hand.
$ bash <(curl -fsSL
   dureclaw.baryon.ai/install)
✓ Server + MCP + Tailscale
SCENE 02 0:15 – 0:45
One-line install — server + automatic MCP registration
In the Mac terminal: bash <(curl -fsSL dureclaw.baryon.ai/install)

Handled automatically: start the Phoenix server in the background → generate OAH_SECRET → register the Claude Code MCP → detect the Tailscale IP → print the worker connect command, all in one go.
$ PHOENIX=ws://100.x:4000
   bash <(…/agent)
✓ builder@server connected
SCENE 03 0:45 – 1:05
Connect a worker machine in one line
In the GPU server terminal, paste the command printed by install.sh:
PHOENIX=ws://100.x.x.x:4000 bash <(curl -fsSL …/agent)

✅ builder@gpuserver connected message. Confirm the agent is online in the dashboard at http://localhost:4000.
claude › /두레팀
"Set up the team"
→ fan-out to N machines
SCENE 04 1:05 – 1:25
Ask Claude to build the team
In the Claude Code terminal, type /두레팀

Claude automatically: scans online agents → creates a Work Key → builds the team manifest → assigns roles.

Team status output: orchestrator@mac · builder@gpuserver
SCENE 05 1:25 – 2:30
Two machines at once — The Magic Moment
"Run the frontend build on the Mac and the backend tests on the server, at the same time."

Both terminals move at once. Mac: running npm run build · GPU server: running pytest tests/ in parallel.

Claude collects results from both sides and prints a combined report. Total time: ~50% shorter than running serially.

Install → connect a worker → one-line instruction → parallel run · about 2.5 minutes. The live demos above are captures of the real system.

FIELDBUS GATEWAYS — bring existing equipment and PLCs onto the bus

A gateway normalizes the industrial protocols your equipment speaks, and edgeclaw collects the data. edgeclaw runs next to the gateway (or on an industrial Linux gateway).
